# Food Integrity Project digital design system

This repository is the design system itself: Markdown docs, generated tokens, brand assets and a generated visual showcase.

@docs/design-system/README.md

## Working in this repo

- The docs in `docs/design-system/` are the source of truth. `index.html`, `styles/tokens.css` and the participant pages in `trademark/*.html` are generated by `scripts/build-showcase.mjs`. Never edit them by hand.
- `docs/design-system/trademark/*.md` summarize each program's official trademark use guide for participants. The program guide wins over them; keep them in step with it and never add rules it doesn't contain.
- Colors: edit `scripts/palette.config.json`, then `npm run colors`. That rewrites the scale tables and pairings in `02-color.md` and the palette block in `09-tokens.md`. Never hand-edit content between the `scales`, `pairings` or `palette` markers.
- Semantic token mappings live in the CSS blocks of `09-tokens.md`.
- A PostToolUse hook in `.claude/settings.json` rebuilds the showcase after every edit to a doc, the palette config, the showcase scripts or `public/brand/`. If it reports build-check errors (contrast, palette drift, missing assets, unknown icons, undefined tokens), fix them before finishing.
- The showcase parses the docs' tables by heading and column name. When renaming a heading or a table column in a doc, update the matching lookup in `scripts/showcase/render.mjs`, or the build reports the section as missing.
- Brand values come from the *Food Integrity Project Style Guide* (draft for review). Where it is silent, leave a `TODO(design)` or `TODO(brand)` rather than inventing a value.
- Logos and seals in `public/brand/` are official files. Never redraw, recolor or generate artwork. Add new files to the asset inventory in `04-logos-and-marks.md`.

## Maintenance loop

`.claude/skills/issue-review-loop/SKILL.md` defines how issues and direct commits to `main` are handled: clear issues from org members and collaborators are implemented and merged, unclear ones get questions, and direct edits that skipped the build are regenerated and followed up. Start it with `/loop 1h /issue-review-loop`; run one pass with `/issue-review-loop`.

## Commands

- `npm run dev`: watch and serve at http://localhost:4321 with live reload
- `npm run build`: rebuild once
- `npm run colors`: regenerate scales from the palette config
- `npm run check`: fail if generated files are stale or any build check fails
- `npm run todos`: list open TODOs
